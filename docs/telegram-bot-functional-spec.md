# Telegram Bot Functional Specification

Date: 2026-08-26
Project: Internal IT asset and operations management system
Scope: Telegram bot user experience, identity capture, repair requests, cartridge replacement requests, and administrator workflows.

## Product Intent

The Telegram bot is a lightweight operational front door for staff. It should feel polished, focused, and reliable rather than exposing the full internal system inside Telegram. The bot is intentionally centered on the two workflows that proved useful in real usage:

- Create an IT repair request.
- Create a cartridge replacement request.

Other historical Telegram features, especially inventory management, are not part of the current user-facing Telegram experience.

## User Experience Principles

The bot should present itself as a premium, simple support channel:

- The main menu must stay short and confident.
- Ordinary users should only see repair and cartridge actions.
- The bot should collect Telegram profile metadata automatically from incoming updates where Telegram provides it.
- The bot should invite the user to share contact details and workplace information.
- The workplace means branch and room or cabinet.
- The user should not be blocked if they skip onboarding.
- The first completed repair or cartridge request should remember the chosen branch and room as that Telegram user's default workplace.
- Future request flows should be able to offer the saved workplace and still allow manual override.

## Ordinary User Workflows

### Start and Onboarding

When a user starts the bot:

- The bot clears any stale conversation state.
- The bot sends a welcome message.
- The reply keyboard contains only:
  - IT repair request.
  - Cartridge replacement.
- The bot may start onboarding to collect contact and workplace data.

### Telegram Profile Accounting

For each incoming message or callback, the system should maintain a Telegram profile record with:

- Telegram user ID.
- Telegram chat ID.
- Username.
- First name.
- Last name.
- Language code.
- Bot flag.
- Last interaction timestamp.
- Default branch.
- Default room number.
- Profile completion status.
- Block status.

A blocked profile must not be silently unblocked by a later sync.

### Repair Request

The repair request flow creates a `RepairRequest` record and stores:

- Telegram user ID.
- Username where available.
- Branch.
- Room number.
- Problem description.
- Optional phone.
- Status `нова` by default.

After completion, the selected branch and room are saved as the user's default workplace.

### Cartridge Replacement

The cartridge replacement flow creates a `CartridgeReplacement` record and stores:

- Telegram user ID.
- Username where available.
- Branch.
- Room number.
- Printer information.
- Cartridge type.
- Replacement date.

After completion, the selected branch and room are saved as the user's default workplace.

## Administrator Experience

Administrators use the same Telegram bot, but recognized admins see an additional inline `Admin panel` button in the main menu and can open the panel with `/admin`.

A recognized Telegram administrator is a web `User` whose `telegram_id` matches the Telegram caller and whose role is either:

- `admin`
- `director`

The admin panel must re-check authorization on every callback, not only when rendering buttons.

### Admin Panel Menu

The current admin panel contains:

- Latest repair requests.
- Cartridge replacement history.
- Telegram request statistics.
- Back to main menu.

Legacy inventory administration is intentionally removed from Telegram.

### Repair Request Administration

Administrators can:

- List the latest repair requests.
- Filter repair requests by status.
- Open a request detail view.
- Move a repair request through the allowed status sequence.

Allowed status sequence:

1. `нова`
2. `в_роботі`
3. `виконана`

Direct jumps such as `нова` to `виконана` are rejected.

### Cartridge History

Administrators can view recent cartridge replacement records in read-only mode.

The cartridge panel must not expose repair status update buttons.

### Statistics

Administrators can open compact Telegram request statistics from the admin panel or with `/status`.

The statistics currently include:

- Total repair requests.
- New repair requests.
- In-progress repair requests.
- Completed repair requests.
- Total cartridge replacement records.
- Cartridge replacement records for the current month.

Ordinary users must receive an access denied response for `/status`.

## Removed Telegram Surface

The legacy Telegram admin surface has been removed from the live bot path:

- Old `admin_*` callbacks are no longer routed.
- Old admin inventory actions are no longer exposed.
- Old repair callbacks without the `adminpanel_` prefix are no longer generated by active admin keyboards.
- The legacy `AdminHandler` class was deleted.

If an old Telegram message still contains a historical `admin_inventory` button, pressing it should fall back to an unknown action response instead of opening inventory management.

## Current Known Follow-Ups

The next high-value improvements are:

- Make the saved workplace suggestion visible at the start of repair and cartridge flows.
- Add an admin broadcast interface from the web admin panel using Telegram profiles.
- Add per-user Telegram profile management in the web admin panel.
- Add richer request detail actions such as assignment, comments, or internal notes once the desired admin workflow is defined.
